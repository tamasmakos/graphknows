You are triaging open GitHub issues for this repository. Use `gh`. If it is not on PATH, fall back to "/c/Program Files/GitHub CLI/gh.exe" (quote it).
List open issues with `gh issue list --search "is:open is:issue -label:\"needs-triage\"" --limit 50`. The -label filter is REQUIRED: issues still carrying "needs-triage" were filed by an agent and have not been reviewed by a human yet.
Pick at most 1 that are concretely fixable in code.
Skip anything that is a question, a discussion, a duplicate, blocked on a decision, or too vague to implement.
A ticket may declare its dependencies in a "## Blocked by" section listing other issue numbers. For every candidate that has one, check each blocker with `gh issue view <n> --json state,title`. If ANY blocker is still open, skip the candidate and give "blocked by #<n>" as the reason -- its blockers must land first or you would be implementing against code that does not exist yet.
Also skip anything that is a release request or asks for a version bump -- this workflow does not release.
Also skip any issue that already has work in flight: check `gh pr list --state open --json number,headRefName,title` and `git ls-remote --heads origin "fix/issue-*"`.
Report every skip under "skipped" with the reason.
Read each candidate's full body and comments (`gh issue view <n> --comments`) before judging it.
Then, for EACH picked issue, sequentially (never in parallel):
  1. `git fetch origin`
  2. from the repo root: `git worktree add ../gk-issue-<n> -b fix/issue-<n> origin/main`
  3. record the ABSOLUTE path of that worktree in DRIVE-LETTER form -- `C:/Users/User/Documents/dev/gk-issue-<n>`, not `/c/Users/...`. Later stages mount that path into docker, which needs the drive letter.
If a worktree or branch for an issue already exists locally, reuse the DIRECTORY rather than failing --
but never trust its commits as they stand, because a leftover branch was cut from an older base.
Before any work starts on a reused branch, put it on the current tip:
  a. `git -C <worktree> fetch origin` then `git -C <worktree> rebase origin/main`
  b. If the rebase reports conflicts, STOP for that issue: `git -C <worktree> rebase --abort`, skip the
     issue, and give the conflict as the skip reason. A leftover branch that disagrees with the tip is a
     human's call, not something to resolve on the way past.
  c. If it rebases clean, confirm it: `git -C <worktree> log --oneline origin/main..HEAD` is now only
     this issue's own commits. Anything you do not recognise means the branch is not what its name claims.
  d. Set resumed_from to the commits it carried over (or "" when the branch was created fresh this run),
     so the run report says the car resumed rather than started clean.
Do not read source files or plan any fix -- that is the next phase's job.
