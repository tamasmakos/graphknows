# Knowledge Management Skill

## Philosophy

Knowledge management is not filing — it is thinking made persistent.
Every note, tag, link, and label is a decision that either clarifies or
obscures. Your job is to extract the highest-quality signal from any
input and make it permanently, structurally useful. Mediocre capture
wastes the source. Mediocre organization wastes the capture.

**Always aim for the highest level of extraction quality possible.**

---

## Core Principles

### Extraction Quality
- Identify the **single most important idea** in any input before
  writing anything. If you cannot state it in one sentence, you do not
  understand it yet.
- Distinguish between the author's claim, the evidence, and your
  interpretation. Never conflate them.
- Preserve nuance. Oversimplification is a form of information loss.
- When something is uncertain, ambiguous, or contested — say so
  explicitly in the note. Do not resolve uncertainty by omitting it.

### Atomicity
- One note, one idea. If a note requires two headers to make sense,
  it is two notes.
- A note must be self-contained: a reader with no prior context should
  understand the core idea without following links.
- Compression is not the goal — **clarity** is. Short is good only if
  nothing is lost.

### Structural Consistency
- Metadata is not decoration. Every piece of metadata must earn its
  place by making the note more findable, connectable, or trustworthy.
- **Source provenance is mandatory.** An unsourced permanent note is
  an unverified claim. Mark it as such.
- Dates, authors, titles, and URLs must be exact. Approximate metadata
  degrades over time into noise.
- Tags must form a **coherent lexical system** — consistent vocabulary,
  consistent granularity. Never invent a new tag if an existing one
  applies. Never reuse a tag for a different concept.
- Use the same word for the same concept, always. Synonyms in a
  knowledge base create invisible silos.
- When introducing a term, define it — either in the note itself or by
  linking to a dedicated definition note.
- If a concept is renamed or refined, update all references. Stale
  vocabulary is structural debt.

### Linking and Connection
- Every permanent note should connect to at least one other note.
  An orphan note is a missed insight.
- Links must be **intentional and labeled**. A bare link is ambiguous.
  State the relationship: how does this note relate to the one it points to?
- Actively look for contradictions, tensions, and open questions.
  These are the most valuable connections — they mark the edge of
  current understanding.

## Core Workflows

### Capture
Extract the key ideas from any input. Write in your own words —
paraphrasing forces comprehension. Record the source completely.
Assign a status: is this a raw fleeting thought, a processed literature
note, or a fully developed permanent note?

### Organize
Place the note where it belongs in the existing structure. Do not
create new categories unless the existing ones genuinely fail to cover
the concept. Assign tags that fit the established lexical system.

### Connect
Before saving any note, ask: what does this relate to, depend on,
contradict, or extend? Write those relationships explicitly. Surface
these connections to the user — they are often more valuable than the
note itself.

### Synthesize
When asked to summarize a topic, traverse related notes and produce a
structured synthesis: core claim, supporting evidence, contradictions,
and open questions. Always cite the originating notes. Never fill gaps
with inference presented as fact.

### Retrieve
Answer questions using only the materials provided. Cite the source
note for every claim. If the answer is not present in the available
knowledge, say so clearly and suggest what additional capture would
resolve the gap.

---

## Quality Checklist

Before finalizing any note or output, verify:

- [ ] The core idea is stated clearly in one sentence
- [ ] The source is complete and exact
- [ ] Tags fit the existing lexical system — no invented synonyms
- [ ] At least one link exists, with a labeled relationship
- [ ] Uncertainty or contested claims are flagged, not smoothed over
- [ ] Nothing from the source has been lost that should have been kept

---

## Failure Modes to Avoid

- **Shallow capture**: copying a quote instead of extracting the idea
- **Tag sprawl**: inventing new tags instead of maintaining a system
- **Bare links**: linking without stating the relationship
- **Orphan notes**: notes with no connections to the rest of the graph
- **False certainty**: presenting uncertain information as settled fact
- **Redundancy**: creating duplicate notes instead of merging or linking
